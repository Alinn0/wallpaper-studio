# 首页、列表、资源权限与预览缓存关联复审

日期：2026-11-08。版本保持 1.0.2。范围是“首页已有预览 → 打开列表 → 切页/隐藏恢复 → 重启”，并检查来源模式、配置提交和缓存淘汰。保留所有既有未提交改动。

## 修复前证据

上一轮只检查了磁盘缓存命中及预览生成次数，不能据此判断同一 Webview 是否保留。这次用原安装版增加页面 ready 和图片节点检查，实际复现打开列表后 ready 从 2 增至 3，日志 `.panel-lifecycle-before.log`。

本机 VS Code 的 `$setOptions` 会设置 contentOptions；其 setter 检测 localResourceRoots 改变后调用 doUpdateContent，重新发送整个 HTML。原来的 `ensureRootForFile` 在发现每个新媒体目录、场景预览页目录时反复修改 options，导致面板内容重建。前端重建又先使用默认 file 模式，所以 Wallpaper 列表短暂出现本地选择按钮，内存中的首页图片也丢失。

## 一并处理的关联问题

| 路径 | 处理 | 验证 |
| --- | --- | --- |
| 初始资源访问范围 | HTML 首次设置前覆盖缓存目录、当前媒体、本地导入、目录及当前账号播放列表；只提取路径，不预扫项目属性；选定 Wallpaper Engine 工作坊覆盖应用资源根 | 已知资源访问不调用页面 options 更新；真实新目录列表不增加 ready |
| 必要的新位置授权 | 同一批新增目录合并一次更新；不在每张列表图片上反复触发 | 两个新导入目录仅一次选项更新的回归 |
| 来源模式首帧 | HTML 注入宿主来源与会话标识，避免默认 file 闪回 | 三模式首帧回归、实际 Wallpaper 列表 MutationObserver |
| 同一 HTML 权限重载 | 使用同一会话已确认来源；新宿主会话仍采用当前共享来源 | 同会话/新会话恢复测试；该快照不是另一份用户偏好 |
| 账号发现 | 正在解析时记住同一已识别账号，不重新启动同一轮列表读取 | 真实完整解析次数为 1、独立回归 |
| 模式提交 | 请求守卫同时进入共享库锁内的修改函数；旧请求即使最后拿到锁也不写回旧模式 | 逆序执行提交的回归，保留最新 folder |
| 首页预览缓存 | 当前精确帧和基线帧在原缓存预算中优先保留，卸载时释放保护；移除无文件版本的旧路径回退 | 超出字符及条数预算仍保留当前图，其他缓存正常淘汰，卸载后可被淘汰 |
| 预览请求取消 | 等待缓存的旧请求也能取消；旧异步 finally 不覆盖新请求的加载状态 | 既有取消回归与缓存恢复回归 |

## 实际交互验收

使用真实 28 MB 场景和另一个独立目录的场景副本，运行在独立临时状态与工作区。先等首页预览生成，再打开列表，反复切页 3 次，并关闭/重新显示侧栏。

- 冷启动：ready=1、playlistReads=1、homePreviewRetained=true，首次生成并落盘 3 条预览。
- 复用同一数据重启：ready=1、playlistReads=1、homePreviewRetained=true，磁盘命中 5 次，重新生成 0 次，预览运行页请求 0 次。
- 直接比较首页原图片 DOM 节点和 src，打开列表后保持同一节点及地址；MutationObserver 未捕获 Wallpaper 模式变成本地上传按钮。
- 安装目录独立进程复验通过；首页/列表截图已查看。
- 17 份正式回归、TSLint、前端类型检查、干净构建均通过。日志 `.panel-lifecycle-tests.log`、`.panel-lifecycle-cold.log`、`.panel-lifecycle-warm.log`、`.panel-lifecycle-installed-cold.log`、`.panel-lifecycle-installed-warm.log`。
