## 按严重程度排列的问题

### F01 · P1 · 已取消的慢任务仍能写回背景，覆盖后来的关闭操作

位置：`src/FileDom.ts:711`、`:719`、`:721`、`:1040`、`:1144`。

`applyPatch` 获取锁后检查一次 `shouldApply()`，随后等待场景包复制/哈希。等待结束到写 CSS 之间没有再次检查；`clearBackground` 则不使用这把锁，也不检查请求是否仍有效。上层忽略返回结果，无法撤销已经发生的磁盘写入。

触发：B 正在准备 → 用户关闭背景，或切到无候选来源/重置 → 关闭成功 → B 的准备稍后结束，重新写入 B 的 CSS。加载器下一次因点击、焦点或启动轮询读取 CSS 时，旧背景可能重新出现，而 runtime 记录依旧是关闭状态。

隔离探针调用真实 `FileDom.applyPatch/clearBackground/saveCssContent`，只用等待门替代慢复制，得到 `cleared=true`、`resurrected=true`、`patchResult=true`。

建议：准备资源可在提交锁外执行；写入前在同一个提交协调器中重新检查请求身份。关闭和应用必须遵守同一锁及提交规则，并避免可见 CSS 被分段覆盖。

### F02 · P1 · 外观更新会作废正在加载的新壁纸

位置：`src/PickList.ts:81`、`:272`、`:846`；`src/extension.ts` 的外观配置命令及外部设置监听。

手动选择、恢复背景和外观重应用共用 `_updateSeq`。B 加载期间改透明度/模糊，`applyCurrentAppearance` 因存在活动更新返回 false，调用者退回 `needAutoUpdate`。该路径读取仍成功保存的 A，重新安装 A 并推进序号，导致 B 被当成过期任务丢弃。FPS、尺寸、混合模式也会走重应用旧背景的路径。

隔离结果：安装请求顺序为 `B.pkg → A.png`，B 最后即使返回成功，`userSelectionApplied=false`，当前仍为 A。

建议：将“选择身份”和“外观版本”分开。加载中的参数变更应合入待选 B，或在 B 成功后补应用；不能通过重应用 A 取消用户选择。

### F03 · P1 · “准备成功”被当成“渲染成功”，真实场景报错不能恢复播放记录

位置：`src/PickList.ts:793`、`:804`、`:877`；`src/FileDom.ts:2208`、`:2219`。

宿主在 `dom.install()` 写好运行文件后就保存当前/上一张，并结束临时 loading。真正的解包、纹理上传、脚本和 WebGL 渲染发生在之后。浏览器收到 `scene-error` 只清标记并输出日志，没有把失败回传为此次切换失败，也没有回滚持久记录。

触发：文件头合法，但包体损坏、脚本执行失败或运行时挂载失败。界面会把它记成当前壁纸；“失败不替换原记录”的保证只覆盖了准备阶段，不能覆盖真正的场景运行失败。

这是静态链路确认。本次没有把损坏包应用到用户真实背景。现有首帧 smoke 验证了一份有效场景，但不验证损坏场景的状态回滚。

建议：明确区分 selected/preparing/ready/failed，在收到对应请求的真实 ready 后再确认成功；失败消息应更新宿主状态和面板，并保留可恢复的旧配置。

### F04 · P2 · 共享库异常会再次让整个侧栏无法注册

位置：`src/sharedLibrary.ts:27`、`:44`；`src/extension.ts:32`、`:171`。

`library.json` 解析失败或初始化拿锁失败，会使 `createSharedLibraryContext` 直接拒绝。激活函数先 await 它，之后才注册 Studio。因此一个配置文件损坏就使面板及面板中的恢复入口不可用。

探针写入临时损坏库，确认上下文创建拒绝。保留原文件、防止覆盖损坏数据是正确的；但不应因此连错误展示和恢复 UI 也无法打开。

建议：先注册可显示故障的 UI，库不可用时进入明确的受限状态；保留坏文件并提供恢复入口，不静默覆盖。

### F05 · P2 · 默认透明度的产品语义和真实实现冲突

位置：`src/settingsStore.ts:41`、`:42`；`src/FileDom.ts:1517`、`:1591`、`:2231`。

注释声明“默认 0，壁纸原样显示”，但 0 被直接用于图片、视频和场景层的 opacity，实际完全不可见。首次使用及重置都采用这个默认值，可能出现“列表有选中、资源也加载成功、背景却看不到”。

探针从真实默认设置生成图片 CSS，确认 `opacity:0`。具体应采用什么默认强度需要确认产品意图；至少注释、文案和行为必须统一，不能直接按注释反向解释现状。

### F06 · P2 · “清除所有缓存与配置”没有清除全部磁盘缓存

位置：`src/StudioViewProvider.ts:949`、`:983`。

重置只清 ThumbnailStore 及部分前端缓存，未清 `scene-assets`、其索引、`scene-preview`。旧的场景能力注册也不会作为重置的一部分统一撤销。

探针确认重置完成后场景包和预览页仍存在。按钮名称、此前文档和实际后果不一致。

建议：由统一缓存管理入口做清理，协调活动读取；清配置、清可重建缓存应有明确范围，原始壁纸始终保留。

### F07 · P2 · 重置中途失败被吞掉，留下混合状态

位置：`src/StudioViewProvider.ts:999`、`:1006`；`src/thumbnailStore.ts:229`。

重置先清 runtime 和逐个库键，再调用设置重置；设置写入失败只 warning，关闭背景命令失败也忽略，最后继续推送状态。用户得到的是部分已清、部分未清的状态，不能可靠知道哪一步失败。

探针让 `resetSettings` 抛出磁盘错误，`resetAllState` 仍正常完成并发出最终状态通知。

建议：按步骤返回清理结果，保留失败项和重试入口；重置开始时先取消在途选择/属性写入/缩略图任务，避免清理过程中被旧任务重新填充。

### F08 · P2 · 磁盘有界，但多个前端图片缓存无界增长

位置：`webview/src/composables/useScenePreview.ts:42`、`:429`、`:487`；`webview/src/views/LocalGalleryTab.vue:222`、`:227`。

`useThumbnailCache` 和磁盘缩略图限制 300 条，但场景 preview 的模块级 cache、列表自身的 pkgFrames/mediaFrames 不执行相应淘汰。场景属性变化还会生成新键。面板保留上下文，单纯切页不会清这些容器。

探针依次访问 1000 个预览键，场景 cache 保留 1000 项。虚拟列表只限制 DOM 行数，无法限制这些 dataURL 占用的内存。

建议：图片只由一个有条数和字节预算的缓存持有；组件保留键或可淘汰引用，不另复制一套永不裁剪的字典。

### F09 · P2 · 取消客户端不取消磁盘读取，过期工作继续占锁和内存

位置：`src/sceneTransport.ts:5`、`:31`；`src/wallpaperScene.ts:103`、`:130`、`:165`；`src/FileDom.ts:1180`。

传输 Reader 无 AbortSignal。客户端关闭只在读取完以后阻止 send，已经开始的读取继续；场景准备中的哈希和复制也没有请求取消接口。缓存锁覆盖完整读取，过期大包可继续占锁，让最新选择等待。

探针确认客户端关闭后 reader 仍完成。这里不否定持锁读取的必要性；问题是缺少协作取消、读任务复用和总并发/字节预算。

建议：取消信号贯穿准备和传输链，等待锁前后均检查；相同内容读取合并，限制重型并发，并在保持文件一致性的前提下缩短独占区间。

### F10 · P2 · 多窗口轮播仍是多套计时器竞争同一份背景

位置：`src/PickList.ts:301`、`:312`；`src/windowBackground.ts` 的工作区键与共享 CSS 选择。

每个扩展宿主有自己的计时器和请求序号，同工作区却共用 CSS/记录。窗口间没有统一选择顺序或调度租约。窗口 A 成功后只重置 A 的计时器，B 的旧 tick 可以紧接着覆盖。

这是既有问题，本次确认仍存在；没有宣称完成真实多窗口时间轴验收。

建议：按工作区选出轮播调度者，或建立可续期租约；实际切换时间、固定/取消固定应通知其他窗口。

### F11 · P2 · runtime 能读新值，却不能主动通知其他窗口更新

位置：`src/runtimeStore.ts:92`；`src/windowBackground.ts:189`；`src/sharedLibrary.ts:105` 对比。

library 有文件监听；runtime 只有同步读取和本宿主事件。同工作区另一个窗口换图或固定后，本面板可能仍显示旧标题/图钉，直到碰到别的状态推送。不能把同文件存储当作实时共享已经完成。

建议：为 runtime 引入独立订阅和版本号，且与轮播调度规则一起设计，避免只补一层重复轮询。

### F12 · P2 · 图片/视频缩略图只按路径缓存，替换同名文件后可能一直显示旧图

位置：`webview/src/views/LocalGalleryTab.vue:249`、`:308`、`:313`；`webview/src/views/HomeTab.vue` 的 previewThumbnail。

场景输入 URI 带文件签名，但普通图片/视频的缩略图键是路径。原路径内容替换后，缓存仍命中；捕获函数发现已有图会直接返回。刷新列表不会主动清理这类缩略图。

建议：三种媒体统一以规范化路径及文件签名标识内容；刷新和文件变化都应有定向失效入口，不靠全量重置恢复。

### F13 · P2 · 活跃 CSS 可能按年龄被误删，404 又会清掉旧背景

位置：`src/FileDom.ts:406`、`:427`、`:2424`；`src/backgroundSoftWrite.ts:40`。

启动清理仅按 CSS mtime 超过 7 天判断旧文件，只排除启动窗口自己的文件。另一个长期打开且没改背景的工作区文件也可能被删。独立 soft-write 模块没有生产调用方，不能假定它在保活。

加载器 `fetch(url).then(r => r.text())` 没有判断 `r.ok`，HTTP 404 的错误正文会被当作新的 CSS，并把场景/视频配置置空。代码注释“读取失败保留已有样式”只覆盖 Promise 拒绝，不覆盖 HTTP 错误响应。

静态链路确认，未在用户真实应用目录模拟删除。建议加入活动租约/记录核对，读取时先校验响应状态及必要标记，确认有效才替换 lastCss。

## 其他需要记录但不夸大为已复现故障的边界

- code-server 视频转发失败后返回 undefined，初始化退回 `vscode-file`，在浏览器环境下通常不可用，却可能仍完成资源安装并保存路径。应让明确的不可用传输失败向上传播。`externalAssetUrl` 返回地址后直接拼 `?mime=` 也没有保留原有 query 的处理。这两点需真实远程环境验收。
- 预览超时主要在 ready/投递后计时，包体 fetch 和 arrayBuffer 之前没有覆盖完整的统一 deadline，远程/慢存储可能长时间占住预览队列。
- reset 的多文件、多键操作并不是一个事务，其他窗口可能观察到中间状态；清理过程中新的写入也需要明确规则。
- 工作区当前路径写入磁盘失败时，资源可能已经生效但播放记录未提交。需要与 F03 一起定义失败后的恢复规则，而不是仅保证“磁盘没被写坏”。

## “屎山”具体体现及拆分顺序

1. **FileDom.ts：2687 行。** 处理安装目录定位、备份、权限、补丁、CSS、场景准备，以及大量内嵌浏览器代码。浏览器代码在字符串里，类型检查不能覆盖其内部状态契约。取消和提交因此散落在不同位置，F01/F03 正是实际代价。
2. **StudioViewProvider.ts：1319 行。** 同时负责桥接消息、库操作、解析播放列表、缩略图、外观属性、重置与 HTML/CSP，无法独立说明每条操作的事务边界。
3. **PickList.ts：947 行。** 旧 QuickPick、输入框、自动轮播、新 UI 应用入口共用静态状态和 updateDom，`_updateSeq` 同时充当多类操作的取消开关，造成 F02。
4. **状态所有者过多。** 设置、共享库、runtime、临时选择、CSS 内配置、真实浏览器场景都能表达“当前状态”，但没有统一规定谁确认成功、谁回滚、谁向其他窗口广播。
5. **有实际遗留/重复模块。** `backgroundSoftWrite.ts` 没有生产调用、却被独立回归覆盖并列在 README 的运行行为中；前端 `utils/color.ts` 无调用方，HomeTab 又有另一套颜色转换。不要据此删除仍有入口的兼容代码，应先确认可达性。
6. **文档和注释漂移。** 旧设置审查仍写 globalStorage 缩略图、localStorage 覆盖帧和“未安装”；代码残留在线源、会话 CSS 与旧透明度范围的注释。失真的说明会导致下一轮改动依据错误前提。

建议顺序：

- 第一阶段：先补 F01/F02/F03 的跨层失败与竞态测试，建立统一的选择/准备/提交/ready/失败状态；关闭操作也进入同一协调器。
- 第二阶段：缓存服务统一拥有五包缓存、缩略图预算、失效、取消和重置；移除组件内重复持有的无界图片副本。
- 第三阶段：独立 runtime 通知和工作区轮播协调，解决跨窗口竞争。
- 第四阶段：先把浏览器运行时从字符串提取为独立文件，再拆 Provider 的消息处理与业务服务，最后裁剪确认不可达的旧菜单和迁移逻辑。

## 为什么现有测试没挡住这些问题

`scripts/test-review-regressions.js` 在关键选择竞态中替换了整个 FileDom，能证明“不提交过期 runtime”，但无法证明“实际 CSS 没被过期任务覆盖”。安装 smoke 的提前选择测试也临时替换 install，真实首帧验证则是另一段独立流程，尚未把一次完整选择、真实写盘、真实失败和关闭操作串在同一用例里。

这不使已有测试失去价值，但 13 份通过不能等同于完整切换事务已经正确。新增探针保留为 `scripts/audit-state-boundaries.cjs`，优先将其转成修复后期望正确行为的持久回归。
