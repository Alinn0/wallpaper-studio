## 仍存在的风险 / 技术债

### P2：同工作区多窗口的轮播调度尚未集中

位置：src/PickList.ts 的 startAutoRandomTask、src/windowBackground.ts 的工作区状态。
每个宿主有自己的 setInterval，但同工作区共用 CSS 和持久化背景。多个窗口同时开启时可能分别选图、先后覆盖；一次切换只重置执行窗口的计时。固定记录能阻止下一次自动选图，但没有全局单一调度者。建议按工作区加租约或选主，并广播实际换图时间。该既有风险本轮未扩大范围重构。

### P2：runtime 播放状态与面板缺少独立实时订阅

位置：src/runtimeStore.ts、src/StudioViewProvider.ts。
库数据已有文件监听，runtime 仍以读取最新文件为主；同工作区另一窗口切换后，当前面板可能要等下一次状态推送才更新。建议后续统一播放状态通知，不应把 library 的通知当作 runtime 的通知。

### P2：单一大类混合运行环境和职责

- FileDom.ts 约 2,700 行，混合补丁写入、权限处理、媒体 CSS 和约千行浏览器运行时代码字符串。字符串内部无法获得完整的宿主 TypeScript 检查。
- StudioViewProvider.ts 约 1,300 行，混合消息协议、播放列表加载、缩略图、属性应用与重置。
- PickList.ts 约 930 行，混合旧快捷菜单、背景应用边界、轮播和输入处理。

有明显历史包袱和耦合，属于“需要渐进拆分的可维护项目”，不能仅因行数断言必须推倒重写。优先提取浏览器运行时代码，再分离库操作、播放调度与 UI 消息路由；每步保留现有场景交接与竞态测试。

### P3：兼容入口与迁移逻辑需要注明保留期限

旧快捷菜单/命令仍有实际入口，不能只因 Vue UI 已存在就认定无用而删除。删除旧键的迁移代码也不是已删除功能残留的业务逻辑。建议等旧版本迁移覆盖稳定后单独裁剪，避免用户背景和配置丢失。
